## 🏗️ Architecture ปัจจุบัน

### Pipeline Flow
```
API Request
  ↓
Preprocess Job (extract audio + chunking)
  ↓
Redis Queue (transcription_preprocess)
  ↓
Preprocess Worker (6 workers)
  ├─ Extract audio (ffmpeg)
  ├─ Decode audio once (faster-whisper)
  └─ Create chunks (.npy files)
  ↓
Enqueue Chunk Jobs (round-robin to GPU queue)
  ↓
Redis Queue (transcription_gpu0)
  ↓
GPU Worker (1 worker, CUDA_VISIBLE_DEVICES=0)
  ├─ process_transcription_job() (sequential)
  ├─ faster-whisper.transcribe() (blocking)
  └─ Save chunk results to Redis
  ↓
Aggregator Job
  ↓
Redis Queue (transcription_cpu)
  ↓
CPU Worker (2 workers)
  ├─ Fetch chunk results from Redis
  ├─ Merge chunks
  └─ Apply Thai processor
  ↓
Completed Task
```

```python
def process_transcription_job(
    task_id: str,
    file_path: str,
    language: str,
    model_size: str,
    chunk_duration: int = 150
) -> Dict:
    """
    RQ Worker function - ใช้ persistent TranscriptionService

                language=language,
                model_size=model_size
            )
        )
    # ...
```

#### 2. **Faster Whisper Provider** (`app/services/whisper_providers/faster_whisper_provider.py`)

```python
class FasterWhisperProvider(WhisperProvider):
    def __init__(self, config: Dict = None):
        self.default_model = os.getenv('WHISPER_MODEL', 'medium')
        self.base_device = os.getenv('WHISPER_DEVICE', 'cuda')
        self.compute_type = os.getenv('WHISPER_COMPUTE_TYPE', None)
        self.download_root = os.getenv('WHISPER_DOWNLOAD_ROOT', '/workspace/transcription-service/models')
        self._model_cache = {}  # Singleton pattern
    
    async def transcribe(
        self,
        audio_path: str,  # รองรับทั้ง .wav และ .npy
        language: str = "th",
        model_size: str = None
    ) -> TranscriptionResult:
        # โหลด .npy file (pre-decoded audio) เพื่อลด I/O
        if audio_path.endswith('.npy'):
            audio_input = np.load(audio_path, mmap_mode='r')
        
        model = await self._get_model(model_size)
        segments, info = model.transcribe(audio_input, ...)
```

**Features:**
- ✅ รองรับ pre-decoded audio (.npy files) เพื่อลด I/O
- ✅ Model caching (singleton pattern) เพื่อลด loading time
- ✅ CUDA acceleration (faster-whisper + CTranslate2)
- ❌ ไม่รองรับ concurrent inference natively

#### 3. **Video Service** (`app/services/video_service.py`)

```python
class VideoService:
    def decode_audio_once(self, audio_path: str) -> np.ndarray:
        """
        Decode audio file once เป็น NumPy array
        ลด repeated I/O และ CPU overhead
        """
        audio_array = faster_whisper_decode_audio(audio_path, sampling_rate=16000)
        return audio_array
    
    def create_chunks(
        self,
        audio_path: str,
        chunk_duration: int = 90
    ) -> List[str]:
        # 1. Decode audio once
        audio_array = self.decode_audio_once(audio_path)
        
        # 2. Slice array ใน memory
        for i in range(num_chunks):
            start_sample = i * chunk_samples
            end_sample = min((i + 1) * chunk_samples, total_samples)
            chunk_array = audio_array[start_sample:end_sample]
            
            # 3. Save as .npy file (เร็วกว่า .wav)
            chunk_path = chunk_dir / f"chunk_{i}.npy"
            np.save(chunk_path, chunk_array)
        
        return chunk_paths
```

**Optimizations:**
- ✅ Decode audio once (ไม่ decode หลายครั้ง)
- ✅ Save chunks as .npy files (เร็วกว่า .wav)
- ✅ Reduce I/O overhead

#### 4. **Worker Startup Script** (`scripts/pod/start-rq-workers.sh`)

```bash
# GPU Worker (1 worker สำหรับ GPU 0)
CUDA_VISIBLE_DEVICES=0 rq worker \
    --url "$REDIS_URL" \
    --queues transcription_priority,transcription_gpu0 \
    --name gpu0

# Preprocess Workers (6 workers)
for i in {0..5}; do
    rq worker \
        --url "$REDIS_URL" \
        --queues transcription_preprocess \
        --name preprocess-$i
done

# CPU Workers (2 workers สำหรับ aggregator)
for i in {0..1}; do
    rq worker \
        --url "$REDIS_URL" \
        --queues transcription_cpu \
        --name cpu-$i
done
```

**Current Setup:**
- GPU Worker: **1 worker** (gpu0)
- Preprocess Workers: **6 workers**
- CPU Workers: **2 workers**

## ❌ ปัญหาหลัก

### 1. GPU_CONCURRENCY ไม่ได้ทำงาน

**สาเหตุ:**
- `GPU_CONCURRENCY=3` ถูกตั้งค่าใน `.env.runpod`
- **แต่ไม่ได้ถูกใช้ในโค้ด**
- RQ worker process jobs แบบ **sequential**

**Code ที่ควรใช้แต่ไม่ได้ใช้:**
```python
# ใน config/worker_config.py
GPU_CONCURRENCY = int(os.getenv('GPU_CONCURRENCY', '2'))

# แต่ไม่ได้ถูกใช้ใน process_transcription_job()
```

### 2. Sequential Processing

**สาเหตุ:**
- `loop.run_until_complete()` ทำให้ blocking
- GPU worker ตัวเดียว process jobs ทีละตัว
- faster-whisper ไม่รองรับ concurrent inference natively

### 3. Pipeline Starvation

**สาเหตุ:**
- GPU รอ chunks จาก queue
- Preprocessing → GPU → Aggregation pipeline
- แต่ละ stage มี bottleneck

## 💡 คำแนะนำการแก้ไข

### Option 1: ใช้ Multiple GPU Workers (แนะนำ) ⭐

แม้มี GPU 1 ตัว แต่สามารถ start **multiple GPU workers** เพื่อ process chunks พร้อมกัน

**Implementation:**
```bash
# Start 2-3 GPU workers สำหรับ GPU 1 ตัว
CUDA_VISIBLE_DEVICES=0 rq worker --name gpu0-worker1 ...
CUDA_VISIBLE_DEVICES=0 rq worker --name gpu0-worker2 ...
CUDA_VISIBLE_DEVICES=0 rq worker --name gpu0-worker3 ...
```

**ข้อดี:**
- ✅ ง่ายต่อการ implement
- ✅ GPU utilization เพิ่มขึ้น
- ✅ ไม่ต้องแก้โค้ดมาก

**ข้อเสีย:**
- ⚠️ แต่ละ worker ต้อง load model เอง (เพิ่ม memory)
- ⚠️ อาจเกิด memory contention

### Option 2: ใช้ Threading/Multiprocessing ใน Worker

ปรับ `process_transcription_job()` ให้ใช้ `ThreadPoolExecutor` เพื่อ process multiple chunks concurrently

**ข้อควรระวัง:**
- ⚠️ faster-whisper อาจไม่ thread-safe
- ⚠️ ต้องใช้ lock สำหรับ model access

### Option 3: ปรับ Architecture

- เพิ่ม preprocessing workers
- ใช้ batch processing
- ปรับ pipeline architecture

### Option 4: ลด Chunk Duration

- ลด `chunk_duration` จาก 90s → 60s หรือ 45s
- เพิ่ม parallelism ในการ process chunks
- แต่ต้องระวัง: อาจเพิ่ม overhead
